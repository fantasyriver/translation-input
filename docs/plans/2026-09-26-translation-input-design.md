# macOS 全局翻译输入工具：可行性与设计草案

日期：2026-09-26
状态：开发 MVP 已实现；2026-09-26 用户确认客户端与轻量服务端一起开发，首版官网分发、保留自动回填、后续支持收费。实际验证与限制见 `../manual-testing.md`。

## 用户目标

- 可自定义全局快捷键，默认 Option + Space。
- 唤起轻量悬浮输入框，支持用户现有输入法及多语言输入。
- 输入框右侧提供目标语言选择和确认按钮。
- 确认后经服务端大模型翻译，将译文插入唤起前的输入位置。
- 只支持 macOS；简洁、鲁棒、快速、低内存、低系统侵入。
- 先分析可行性、给出方案，再实施。

“插入原输入位置”是依据第 5 条目标做出的产品解释。目标语言与当前输入法独立。

## 推荐路线与替代方案

推荐 Swift + AppKit 原生菜单栏应用。核心窗口采用 NSPanel，输入区使用 NSTextView；系统输入法负责组合输入和候选词，工具只处理已提交的文字。原生设置页面满足第一版需求，无须引入网页运行时。

替代方案：

| 路线 | 优点 | 代价 | 判断 |
| --- | --- | --- | --- |
| 原生菜单栏应用 | 系统交互可控，依赖少，可直接复用现有输入法 | 需要处理权限及跨应用焦点 | 推荐 |
| InputMethodKit 输入法 | 可直接参与文本输入协议 | 输入源安装/切换、输入会话及与既有输入法配合更复杂 | 不符合首版轻量目标 |
| Electron / Tauri | Web UI 开发方便 | 引入额外运行时或桥接层，系统交互仍需原生代码 | macOS 单平台收益有限 |

支持范围建议 macOS 14+，首先在当前 Apple Silicon 机器验证；Intel 二进制和兼容性单独验证后再宣称支持。跨应用写入采用非沙盒应用路线；正式外部分发使用 Developer ID 签名和公证。首版不以上架 Mac App Store 为目标。

## 交互

1. 用户把光标放到目标应用的输入区，按 Option + Space。
2. 记录原应用 PID、窗口、可获得的焦点元素和选区，仅在本地内存保存。
3. 在当前屏幕展示约 560 像素宽、随内容有限增长的悬浮面板；首版优先稳定定位，光标附近定位作为后续增强。
4. 输入区获得键盘焦点；用户可使用系统快捷键切换已安装的输入法。
5. 右侧选择目标语言，默认英语并记住上次选择；首版可提供中、英、日、韩、法、德、西班牙语等选项。
6. 点击“确定”或 Cmd + Enter 翻译并插入；Enter 默认换行。处于 marked text 组合状态时让输入法先完成候选，不能把候选确认误当翻译提交。
7. 请求期间显示翻译状态和取消操作，禁止重复提交。用户主动离开面板时取消自动插入意图，已返回的结果仍可复制。
8. 译文完整返回后恢复目标应用与输入焦点，经校验后插入一次。仅插入文本，不替用户发送聊天消息或执行终端命令。
9. 失败保留原文与已得到的译文，允许重试或明确点击复制。

## 架构

客户端单进程、事件驱动：

- AppController：菜单栏、生命周期与设置。
- HotKeyManager：RegisterEventHotKey、快捷键录制和注册失败提示；换键时保留可用旧配置直到新键注册成功。
- InputPanelController：NSPanel、NSTextView、目标语言与状态提示。
- TranslationClient：URLSession、请求取消、超时与响应校验。
- InsertionCoordinator：目标捕获、焦点恢复、写入与降级。
- Preferences / Credentials：UserDefaults 保存普通偏好，Keychain 保存访问令牌。

不注册自定义输入源，不安装驱动，不使用常驻高频轮询。快捷键方案避免全局键盘监听；自动回填使用辅助功能权限。无权限时仍允许输入和翻译，提供手动复制模式。

## 跨应用写入与明确边界

这是技术风险最高的部分，先于模型接入验证。

- 在已验证兼容、选区属性可写的标准文本控件上，可以通过 Accessibility 写入选区，避免碰剪贴板。
- 常规兼容路径为临时写入译文到系统剪贴板，恢复焦点后发送一次 Cmd + V。不能直接改整段 AXValue，否则可能覆盖整个输入框或破坏编辑器状态。
- 写入前校验原应用仍存活、窗口/焦点符合当前会话。目标消失、选区变化或焦点不确定时保留译文并提供复制，避免向其他应用插入。
- 写入结果不明确时，不自动尝试第二条写入路径，避免重复插入。
- macOS 没有适用于所有应用的“粘贴消费完成”回执。不能把发出按键事件描述为可靠验证了插入成功。
- 剪贴板恢复只在已验证消费完成且 changeCount 仍属于本次写入时进行；无法确认时保留译文并提示。不能使用固定几十毫秒延迟后无条件恢复，也不能覆盖用户后来复制的新内容。
- 第一版可先实现受控粘贴路径，在兼容性验证后增加标准文本控件的直接写入路径。剪贴板行为要在说明中明确。
- 密码框、系统安全界面、远程桌面、游戏、自绘编辑器和禁用粘贴的控件不承诺自动回填。全屏、多屏、Spaces、输入法候选窗口需要真机测试。

## 服务端接口草案

已有接口则适配；尚无服务端时建议独立轻量 Go HTTP 服务。客户端仅保存本工具的访问令牌，模型密钥存服务端环境变量或密钥管理系统。首版不需要数据库。

`POST /v1/translate`

请求示例：

```json
{"request_id":"uuid","text":"你好，明天可以开会吗？","source_language":"auto","target_language":"en"}
```

响应示例：

```json
{"request_id":"uuid","translated_text":"Hello, can we have a meeting tomorrow?","target_language":"en"}
```

- HTTPS、认证、长度限制、速率限制与结构化错误。
- 开发环境可以使用回环地址 HTTP；不能把明文公网地址作为默认生产配置。
- 系统指令固定为忠实翻译、只返回译文、保留段落/链接/代码；用户文本视为待翻译数据，不能作为新的系统指令执行。
- 由模型在同一次请求中理解源语言，避免为语言检测额外调用模型。
- 首版一次性返回完整译文，避免向原应用流式插入半成品。后续如果需要可仅在面板中流式预览。
- 建议初始上限 10,000 Unicode 字符、客户端总超时约 20 秒；以实测调整，区分超时、网络故障、认证失败、限流和上游错误。
- 仅上传用户在面板中确认提交的文本，不上传原应用全文、屏幕、窗口标题或剪贴板备份。
- 默认不持久化翻译正文；日志仅记录请求 ID、耗时和错误类别。

## 鲁棒性

会话状态：隐藏 → 编辑 → 请求中 → 准备插入 → 已发出插入；失败进入保留内容的错误态。

每次唤起拥有会话 ID，每次提交拥有请求 ID。取消、再次唤起、修改输入或目标语言后旧响应失效，不能触发迟到插入。每次会话至多尝试一次自动写入；重试翻译与重试插入分开处理。请求期间原文快照不可变。

辅助功能授权被撤销时降级；网络请求不阻塞 UI；快捷键冲突报告可观察的注册失败，但不声称能检测所有第三方事件拦截冲突。

## 性能目标（尚未测量）

- 热唤起 P95 目标小于 150 ms。
- Release 构建空闲内存争取控制在 50–100 MB 以内，按实际进程物理内存占用测量；稳定后再收紧预算。
- 空闲时无定时网络请求、无持续键盘扫描，CPU 接近 0。
- 翻译耗时取决于模型、网络、输入长度和输出长度；短文本 1–3 秒仅作为模型选型与部署的优化目标。
- 分别测量热唤起、网络/推理、焦点恢复和插入耗时。

## 实施与验收顺序

1. 原生交互原型：菜单栏、全局快捷键、悬浮输入框、目标语言、输入法兼容。用固定测试文字验证原位置回填，不依赖真实模型。
2. 翻译闭环：接口契约、真实或 mock HTTP 服务、URLSession、取消与错误状态。真实模型端到端验收需要可用接口/密钥。
3. 设置与防错：快捷键自定义、Keychain、会话隔离、权限降级、剪贴板并发变化。
4. 真机验收：TextEdit、Safari/Chrome 网页输入框、VS Code、飞书/微信；中英文和中文候选、长文本、多屏/全屏、切换焦点、断网、迟到响应、权限撤销。只对实际测过的应用与版本宣称兼容。
5. Release 体积/内存/唤起性能；整理构建运行文档与 .app 打包脚本。面向外部分发的签名公证依赖开发者证书和账号。

自动化重点为会话失效、至多写入一次、HTTP 错误与响应校验、剪贴板恢复条件；输入法和跨应用行为必须人工真机验证。
